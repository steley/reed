# Reed

  <img src="packages/app/public/logo.svg" width="72" alt="Reed logo" />
</p>

A personal RSS reader built on Vercel (Hono), Neon (PostgreSQL), and GitHub Actions — static assets and API in one deployment, scheduled refresh in CI.

![Reed — homepage](docs/screenshot.png)

---

## Features

- Multi-user auth: email + password registration/login (JWT session cookie; optional invite code via `SIGNUP_CODE`)
- Folders to organize feeds (drag-and-drop, rename/delete via context menu)
- OPML import/export
- Add RSS 2.0 and Atom feeds by URL
- Hourly background refresh via GitHub Actions; manual refresh-all or per-feed
- Full-text search across article titles and bodies (Postgres pg_trgm), with matched terms highlighted in the list
- Read/unread tracking, auto-mark-read on open; mark all as read per feed or globally
- Unread-only filter toggle and unread-count badges; feeds with fresh unread articles float up in the sidebar
- Sort articles newest or oldest first
- Markdown and HTML article content rendering; full-text extraction for feeds that only summarize (Readability)
- Article titles link to original posts
- Dark/light mode toggle (defaults to light mode)
- Three-pane layout with a collapsible feed sidebar (state persisted; collapses to the article list + reader on desktop, drawer on mobile)
- Adjustable reader text size (Aa button)
- Keyboard shortcuts: `j`/`k` or arrow keys to navigate, `v` to open the original post, `r` to refresh
- Feed health indicator: failing feeds show a red dot with the last error on hover
- REST API is fully `curl`-able — all data endpoints accept `Authorization: Bearer <jwt>` in addition to the session cookie

## Stack

| Layer | Technology |
|-------|-----------|
| Runtime | Vercel serverless functions (Node) |
| Database | Neon (PostgreSQL, HTTP driver) |
| Scheduled refresh | GitHub Actions cron |
| ORM | Drizzle ORM + drizzle-kit |
| HTTP router | Hono |
| RSS parsing | fast-xml-parser |
| Frontend | React 19 + Vite |
| UI | Hand-rolled components + Tailwind v4 |
| Monorepo | pnpm workspaces |
| Linting | Biome |
| Testing | Vitest |

## REST API

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/auth/register` | Register `{ email, password }` (`code` when invite code set) → session cookie |
| `POST` | `/api/auth/login` | Log in `{ email, password }` → session cookie |
| `POST` | `/api/auth/logout` | Clear the session cookie |
| `GET` | `/api/auth/me` | Session check → `{ id, email }` |
| `GET` | `/api/feeds` | List your feeds |
| `POST` | `/api/feeds` | Add a feed `{ url }` |
| `PATCH` | `/api/feeds/:id` | Move feed into/out of a folder `{ folderId }` |
| `DELETE` | `/api/feeds/:id` | Delete a feed and its articles |
| `POST` | `/api/feeds/:id/refresh` | Manually refresh a feed |
| `GET` / `POST` | `/api/folders` | List / create folders |
| `PATCH` / `DELETE` | `/api/folders/:id` | Rename / delete a folder (member feeds become uncategorized) |
| `GET` | `/api/articles` | List articles (`?feed_id=`, `?folder_id=`, `?unread=true`, `?q=` full-text search) |
| `GET` | `/api/articles/:id` | Full article including content |
| `PATCH` | `/api/articles/:id` | Mark read/unread `{ read: boolean }` |
| `POST` | `/api/articles/read-all` | Mark all as read; `{ feedId }` scopes to one feed |
| `GET` / `POST` | `/api/opml` | Export OPML download / import OPML body |

All data endpoints require a session (HttpOnly cookie or `Authorization: Bearer`);
`GET /api/health` and the auth endpoints are public. All responses are JSON.
Errors return `{ error: string }`.

## Development

```bash
# Install dependencies
pnpm install

# Run the API locally on :8787 (connects straight to Neon)
export DATABASE_URL=postgresql://...
pnpm dev

# Run the frontend dev server (proxies /api/* to :8787)
pnpm --filter @reed/app dev

# Run all tests
pnpm test:run

# Type-check all packages
pnpm type-check
```

## Deployment

```bash
# First time: import the repo in Vercel, set the DATABASE_URL and
# AUTH_SECRET project env vars, bind a custom domain.

# Deploy from the CLI (or just push — Vercel builds from the repo)
pnpm deploy
```

The API ships as a pre-bundled `api/index.js` (generated by `pnpm build:api`
from `packages/worker/src/vercel-entry.ts`). After changing `packages/worker`
code, run `pnpm build:api` and commit the regenerated bundle — the pre-commit
hook fails if the committed bundle is stale.

Schema migrations are applied directly to Neon:

```bash
export DATABASE_URL=postgresql://...
pnpm --filter @reed/worker db:migrate
```

The hourly refresh workflow (`.github/workflows/refresh.yml`) needs the
`DATABASE_URL` repository secret.

Tests run against a throwaway Neon branch via `TEST_DATABASE_URL` — they
truncate all tables, so never point it at a database you use. Unset, tests
skip.

## Schema changes

```bash
# Edit packages/worker/src/db/schema.ts, then:
pnpm --filter @reed/worker db:generate   # generates SQL in drizzle/
pnpm --filter @reed/worker db:migrate    # apply to Neon (DATABASE_URL)
```
